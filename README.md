# Протокол совещания — каркас

Прототип локального автопротоколирования по `PLAN.MD`. Сейчас это запускаемая структура приложения, **без обработки записей и генерации протокола**.

## Что уже сделано

- FastAPI и Pydantic: контракты встречи, файла, задачи, реплики, говорящего, темы, показателя, проблемы, поручения и экспорта.
- SQLite: десять таблиц, внешние ключи, каскадное удаление связанных строк, ограничение одной задачи в состоянии `processing`. SQL-модели находятся в `backend/app/schema.sql`; ORM не используется.
- API-заглушки с ответом `501 Not Implemented`. Загрузка не сохраняет запись и не создаёт задачу.
- React/TypeScript/Vite: экраны загрузки/статуса и проверки протокола. Нет демонстрационных транскриптов и поручений. Кнопки будущих правок, утверждения и экспорта отключены.
- Собранный frontend раздаётся FastAPI. Запуск через `python -m backend.app` привязан к `127.0.0.1`; access log отключён.
- Отдельные пакеты `sources`, `processing`, `exporting` обозначают будущие границы реализации.

## Подготовка и запуск

Нужны Python 3.12, Node.js 22.12+ (проверено на 24.19) и pnpm 11. Для каркаса GPU, FFmpeg, LibreOffice и модели не нужны. Первичная установка зависимостей требует сети; само приложение не вызывает внешние сервисы. Запускайте команды из корня репозитория.

Windows PowerShell:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r backend/requirements-dev.txt
Copy-Item .env.example .env
Set-Location frontend
pnpm install --frozen-lockfile
pnpm build
Set-Location ..
.\.venv\Scripts\python.exe -m backend.app
```

Linux / Brev:

```bash
python3.12 -m venv .venv
.venv/bin/python -m pip install -r backend/requirements-dev.txt
cp .env.example .env
cd frontend
pnpm install --frozen-lockfile
pnpm build
cd ..
.venv/bin/python -m backend.app
```

Откройте http://127.0.0.1:8000. Сборку нужно выполнить **до запуска backend**; после первой сборки перезапустите сервер. Без сборки корневой URL возвращает `503` с пояснением. OpenAPI доступен на `/openapi.json`; Swagger/ReDoc отключены, чтобы не подгружать скрипты с CDN.

Для разработки frontend: в каталоге `frontend` выполните `pnpm dev`, оставив backend запущенным. Vite слушает `127.0.0.1:5173`, `/api` проксируется на `127.0.0.1:8000`. При изменении порта backend поправьте proxy в `frontend/vite.config.ts`.

Для удалённой машины используйте SSH-туннель с компьютера разработчика (замените USER и HOST):

```bash
ssh -N -L 127.0.0.1:8000:127.0.0.1:8000 USER@HOST
```

Не открывайте публичный порт и не создавайте публичную ссылку.

## Конфигурация

`.env.example` содержит только примеры, `.env` исключён из Git. Существующие переменные процесса имеют приоритет. Относительные пути разрешаются от корня репозитория.

| Переменная | Назначение |
| --- | --- |
| `DATA_DIR`, `DATABASE_PATH` | Локальный каталог и SQLite; создаются при запуске |
| `FRONTEND_DIST`, `PORT` | Сборка интерфейса и порт backend; адрес запуска фиксирован на loopback |
| `WHISPER_MODEL_PATH` | Будущий локальный каталог faster-whisper large-v3 |
| `PYANNOTE_MODEL_PATH` | Будущий локальный каталог speaker-diarization-community-1 |
| `OLLAMA_BASE_URL`, `OLLAMA_MODEL` | Будущий локальный Ollama и qwen3:8b |
| `FFMPEG_PATH`, `FFPROBE_PATH`, `LIBREOFFICE_PATH` | Будущие локальные исполняемые файлы |
| `HF_TOKEN` | Только подготовка весов; оставить пустым в рабочем окружении |
| `HF_HUB_OFFLINE`, `TRANSFORMERS_OFFLINE` | Флаги будущего офлайн-запуска моделей |

Переменные моделей и внешних программ пока лишь документируют будущую конфигурацию: каркас не загружает модели, не проверяет их наличие и не обращается к Ollama. Команд загрузки моделей здесь ещё нет: они будут добавлены после реализации и проверки соответствующего этапа. До подготовки pyannote необходимо принять условия модели; токен не сохраняется в Git.

## API

`PLAN.MD` задаёт операции, но не URL. В каркасе выбраны следующие маршруты:

| Метод и путь | Назначение / текущее поведение |
| --- | --- |
| `GET /api/health` | `200`: сервер работает, `processing=not_implemented` |
| `POST /api/meetings` | Multipart: `file`, `title`, необязательные `meeting_date` и `timezone`; `501` |
| `GET /api/meetings/{id}/status` | Статус; `501` |
| `GET /api/meetings/{id}/result` | Результат; `501` |
| `PATCH /api/meetings/{id}` | Правки говорящих, реплик, поручений и флаг утверждения; `501` |
| `GET /api/meetings/{id}/exports/{format}` | `docx` или `pdf`; `501` |
| `DELETE /api/meetings/{id}` | Удаление встречи; `501` |

Некорректная форма запроса может получить `422` ещё до заглушки. Неизвестные API-маршруты возвращают `404`. Успешные ответы операций и ошибки конфигурации моделей будут реализованы вместе с обработчиком.

## Проверки

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s backend/tests -v
Set-Location frontend
pnpm build
```

На Linux замените путь Python на `.venv/bin/python`. Тесты создают временную SQLite, проверяют таблицы, внешние ключи, ограничение одного обработчика, каскадное удаление строк, валидацию времени, API-заглушки и раздачу frontend при наличии сборки. Тестовые записи и результаты ML не используются.

## Следующие этапы

1. Сначала сквозной сценарий без UI: сохранение/проверка файла (формат, 200 МБ, 15 минут), FFmpeg mono 16 кГц, один фоновый обработчик и честные ошибки отсутствующих моделей.
2. Локальные ASR и диаризация с временными метками; отдельный источник аудио. Никаких live-адаптеров и WebSocket в первой версии.
3. Ollama: структурированные темы, факты, проблемы, поручения. Проверять ссылки на реплики, неоднозначности и сроки; говорящий и ответственный — отдельные сущности. Нормализовать относительный срок только при известной дате и часовом поясе, сохраняя исходную формулировку.
4. Реальное сохранение правок, сопоставление имён, утверждение и переход к месту записи; подключить UI к рабочим API.
5. DOCX через python-docx и PDF через локальный LibreOffice только из утверждённого состояния. Синие заголовки, светлые шапки таблиц, темы и приложение-транскрипт; проверить длинный текст, кириллицу и казахские символы.
6. Удаление исходника и всех результатов вместе со встречей; транзакции, обработка ошибок и стратегия изменений схемы. Сейчас есть только создание пустой схемы, без миграций и репозиториев CRUD.
7. Проверить три согласованные обезличенные записи: русскую, казахскую, смешанную. При необходимости сравнить распознавание с локальной Sybyrla по плану.

## Ограничения и закрытый контур

Каркас не является готовым продуктом: сохранение, обработка, редактирование и оба экспорта отсутствуют. Лимит размера проверяется в UI и моделях данных; серверное ограничение потока и проверка длительности ещё не реализованы. Не загружайте реальные записи для проверки заглушки.

Для будущего полного тракта план требует GPU от 22 ГБ VRAM, RAM от 32 ГБ и 60 ГБ свободного диска (A10G/L4 или лучше). Проверки GPU и моделей в этой сессии не выполнялись. При нехватке VRAM этапы должны последовательно освобождать GPU.

Аудио, транскрипты, саммари и поручения не отправляются во внешние AI/API и не пишутся в логи. Brev — облачная демонстрационная среда, не закрытый контур заказчика; допускаются только обезличенные и согласованные записи. Для закрытого контура заранее подготовьте зависимости, веса и шрифты и проверьте работу при заблокированном исходящем доступе. Аутентификация, live-конференции, рассылки, СЭД, дашборд исполнения и голосовая идентификация не реализованы.
