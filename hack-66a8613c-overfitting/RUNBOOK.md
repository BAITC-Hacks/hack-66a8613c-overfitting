# Серверный прогон и демонстрация

Этот документ — инструкция, а не отчёт об успешном прогоне. GPU, реальные записи и LibreOffice в текущей среде не запускались. Чеклист ниже заполняется вручную на сервере. На Brev допускаются только обезличенные записи, согласованные для облачной демонстрации; это не закрытый контур заказчика.

## 1. Предварительная проверка на Linux/Brev

Нужны NVIDIA GPU от 22 ГБ VRAM, RAM от 32 ГБ, диск от 60 ГБ, Docker Engine/Compose и NVIDIA Container Toolkit. Зависимости/образ и все веса подготовьте заранее в разрешённой среде; приложение их не скачивает.

```bash
nvidia-smi --query-gpu=name,driver_version,memory.total,memory.used --format=csv
free -h
df -h .
docker version
docker compose version
test -r models/whisper-large-v3/model.bin
test -r models/speaker-diarization-community-1/config.yaml
test -d models/ollama/manifests
test -d models/ollama/blobs
mkdir -p data
test -f .env || cp .env.example .env
export CONTAINER_UID=$(id -u)
export CONTAINER_GID=$(id -g)
docker compose config --quiet
```

Сверьте полный состав весов с README. Проверка существования каталогов не доказывает полноту моделей. При нестандартных путях задайте `CONTAINER_MODELS_DIR`/`CONTAINER_DATA_DIR` и используйте их вместо `models`/`data` в командах. Подсеть `172.30.66.0/24` не должна конфликтовать с инфраструктурой сервера. Не меняйте её только в Compose: адрес также закреплён в сетевой политике backend и стартовых скриптах.

## 2. Запуск и закрытый контур

Если образ уже перенесён: `docker load -i meeting-minutes-image.tar`. Если его ещё нет, соберите отдельно в среде подготовки: `docker compose build`. На рабочем сервере:

```bash
# При переходе с прежнего Compose: сначала дождаться завершения активной задачи.
docker compose down
docker compose up -d --no-build --pull never
docker compose ps
docker compose exec app python /opt/container/healthcheck.py
docker compose exec ollama python /opt/container/healthcheck.py
docker compose exec ollama ollama list
docker compose exec app python -c "import torch; print('CUDA available:', torch.cuda.is_available())"
docker network inspect meeting-minutes_local --format '{{.Internal}}'
docker compose port app 8000
```

Проверяемые ожидания: оба сервиса healthy, в списке моделей `qwen3:8b`, CUDA доступна, сеть internal=true, порт приложения `127.0.0.1:8000`. Порт Ollama наружу не публикуется. Эти ожидания здесь **не отмечены как выполненные**. `ollama list` не загружает модель для генерации; фактическая загрузка проверяется обработкой записи.

Администратор проверяет эффективные правила firewall/Docker и отсутствие у контейнеров дополнительных сетей. Внутренняя сеть ограничивает внешнюю маршрутизацию; при необходимости отдельно блокируется доступ контейнеров к сервисам хоста и внешним сетям. Python-аудит сокетов не заменяет firewall. Не проверяйте изоляцию отправкой записей или текстов во внешние адреса.

С рабочего компьютера откройте SSH-туннель, подставив свои SSH-имя и адрес:

```bash
ssh -N -L 127.0.0.1:8000:127.0.0.1:8000 USER@SERVER
```

Откройте `http://127.0.0.1:8000`. Публичную ссылку не создавайте.

## 3. Один полный сценарий

1. Загрузите согласованную запись через UI: название, реальная дата встречи, IANA-часовой пояс; до 200 МиБ и 15 минут. Сохраните UUID встречи локально. Список встреч после обновления страницы пока не реализован — не обновляйте страницу во время демонстрации.
2. Дождитесь `ready`: WAV → Whisper → pyannote → анализ. При `failed` зафиксируйте безопасный код ошибки; успешный healthcheck не гарантирует работоспособность моделей. Автоматического повтора нет — после устранения причины загрузите запись снова.
3. Прослушайте источники поручений и несколько реплик через плеер. Проверьте время, говорящих, имена, числа, отрицания, сроки, русский/казахский текст. Ссылки должны запускать воспроизведение с нужного времени только после нажатия.
4. Переименуйте спикера, исправьте текст реплики, переназначьте её другому говорящему и отдельно проверьте снятие назначения. Сохраните. Проверьте, что саммари не пересчиталось автоматически, а связанные поручения требуют повторной проверки.
5. Исправьте поручение и срок. Сверьте рассчитанную дату с датой/зоной встречи. Неоднозначная фраза должна дать пустую дату и флаг проверки. Уточните её либо явно подтвердите неизвестный срок после проверки.
6. Проверьте все поручения и снимите флаги. До утверждения экспорт должен быть запрещён. Нажмите «Утвердить», скачайте DOCX/PDF.
7. Сверьте документы с исправленным UI. Затем снова измените реплику: утверждение должно сняться и экспорт заблокироваться. Повторно проверьте и утвердите результат.
8. После демонстрации при необходимости удалите встречу через UI и проверьте удаление её UUID-каталога и недоступность API. Не удаляйте нужные для сверки материалы до завершения проверки.

## 4. Диагностика GPU и PDF — только на сервере

Во втором терминале во время обработки:

```bash
watch -n 1 nvidia-smi --query-gpu=name,memory.used,memory.total,utilization.gpu --format=csv
docker compose exec ollama ollama ps
```

Зафиксируйте пик VRAM и время обработки каждого сценария. Модели должны освобождать память между этапами; при OOM отметьте этап и безопасный код, не объявляйте прогон успешным.

Проверка установки PDF-зависимостей:

```bash
docker compose exec app /usr/bin/soffice --headless --version
docker compose exec app python -c "from docx import Document; print('python-docx import OK')"
docker compose exec app test -r /usr/share/fonts/truetype/dejavu/DejaVuSans.ttf
```

Для утверждённой встречи замените `UUID_ВСТРЕЧИ` её реальным UUID. Команды не утверждают результат и не обходят проверку API:

```bash
MEETING_ID=UUID_ВСТРЕЧИ
curl --fail --silent --show-error "http://127.0.0.1:8000/api/meetings/$MEETING_ID/exports/docx" \
  -o "data/$MEETING_ID/manual-check.docx"
curl --fail --silent --show-error "http://127.0.0.1:8000/api/meetings/$MEETING_ID/exports/pdf" \
  -D "data/$MEETING_ID/pdf-headers.txt" -o "data/$MEETING_ID/manual-check.pdf"
```

При ошибке скачивания файл проверки не считать готовым документом. В UI должны отображаться безопасные ошибки `not_approved`, `libreoffice_missing`, `pdf_conversion_failed` или `export_timeout`. Не включайте приватные документы/ответы API в общие логи или Git.

Откройте DOCX в локальном редакторе, PDF — в локальном просмотрщике. Проверьте шапку, синие заголовки, светлые шапки таблиц, порядок разделов, переносы длинных строк/страниц, исходные фразы и рассчитанные даты, исправленные имена и текст. Отдельно проверьте казахские буквы: Ә Ғ Қ Ң Ө Ұ Ү Һ І. Визуальная проверка обязательна; статус 200 сам по себе недостаточен.
