# Протокол совещания — локальный транскрипт и анализ

Прототип локального автопротоколирования по `PLAN.MD`. Реализован путь **загрузка → сохранение → подготовка WAV → локальный Whisper → локальная pyannote → транскрипт с говорящими → локальный Ollama/Qwen3:8b → саммари, проблемы и поручения**. Правки и документы ещё не подключены. ML-тракт требует подготовленного Linux/CUDA-окружения; лёгкий backend по-прежнему запускается без ML-пакетов.

## Что уже сделано

- FastAPI и Pydantic: контракты встречи, файла, задачи, реплики, говорящего, темы, показателя, проблемы, поручения и экспорта.
- SQLite: сущности протокола, ключевые пункты и таблицы связей с исходными репликами, внешние ключи, каскадное удаление, ограничение одной активной обработки на всех этапах. SQL-модели находятся в `backend/app/schema.sql`; ORM не используется.
- Реальная загрузка MP4/M4A/MP3/WAV/WebM: UUID встречи, нормализация исходного имени, техническое имя файла, серверный лимит 200 МиБ (209715200 байт). Пустой или неподдерживаемый файл отклоняется; частичная загрузка очищается.
- FFprobe проверяет аудиодорожку и длительность до 900 секунд; FFmpeg создаёт WAV mono, 16 кГц, PCM 16-bit. Выходной WAV проверяется повторно. Ошибки безопасно сохраняются в задаче, stderr программ не логируется.
- FastAPI BackgroundTasks последовательно выполняет весь конвейер в одном процессе. Статусы: `queued` → `preparing_audio` → `ready_for_models` → `transcribing` → `diarizing` → `saving_transcript` → `analyzing` → `ready`; ошибка любого этапа — `failed`. Новый `ready_for_models` со `stage=models` — промежуточный статус, после него модели запускаются автоматически.
- Whisper использует CUDA/float16, локальный каталог CTranslate2 и `language=None, multilingual=True`. Сохраняется начальная оценка языка всей записи; она не назначается каждой реплике и не запрещает переключение языка при декодировании.
- Реплика получает говорящего по максимальному суммарному пересечению с его временными интервалами. Дубли одного говорящего не удваивают оценку. Метки `speaker_1`, `speaker_2` получают нейтральные имена «Спикер 1», «Спикер 2» по первому появлению. При пересечении с несколькими спикерами, пробелах и равных оценках ставится флаг проверки; без пересечения говорящий остаётся неизвестным.
- Говорящие, реплики, язык и переход в `analyzing` сохраняются одной SQLite-транзакцией. Ollama получает только заново прочитанные из БД реплики с ID, временем, нейтральным говорящим и текстом. Анализ и финальный `ready` сохраняются второй транзакцией. При ошибке анализа WAV и полный транскрипт остаются доступны; частичный анализ не публикуется.
- React отправляет файл, показывает ошибки сервера и опрашивает статус раз в 2 секунды до завершения обработки. Экран результата показывает саммари, таблицу ключевых пунктов, темы, поручения и транскрипт. Ссылки ведут к исходным репликам; машинные данные отмечены «Требует проверки». Демонстрационных ответов нет.
- Удаление завершённой/ошибочной встречи удаляет её каталог и строки SQLite. Для ожидающих и активных задач, включая ML-этапы, возвращается `409`. Пути из БД не используются для удаления; ссылки и Windows junction запрещены.
- Собранный frontend раздаётся FastAPI. Запуск через `python -m backend.app` привязан к `127.0.0.1`; access log отключён.
- `sources` отвечает за загрузку; `processing/audio.py`, `adapters.py`, `alignment.py` — за подготовку WAV, локальные модели и объединение интервалов; `analysis.py` и `ollama.py` — за проверку анализа и локальный HTTP-клиент. `exporting` остаётся заглушкой.

## Подготовка и запуск

Нужны Python 3.12, Node.js 22.12+ (проверено на 24.19), pnpm 11 и локальные FFmpeg/FFprobe. Для транскрипции нужны CUDA и локальные веса, для анализа — локальный Ollama с заранее подготовленной qwen3:8b (разделы ниже). Первичная подготовка зависимостей может использовать сеть; рабочий тракт использует локальные файлы и разрешённый loopback-запрос к Ollama. Запускайте команды из корня репозитория.

Windows PowerShell:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r backend/requirements-dev.txt
Copy-Item .env.example .env
Set-Location frontend
pnpm install --frozen-lockfile
pnpm build
Set-Location ..
.\.venv\Scripts\python.exe -m backend.app
```

Если `.env` уже существует, сохраните его настройки и не выполняйте повторное копирование. До запуска укажите пути к установленным программам, например:

```dotenv
FFMPEG_PATH=C:/Tools/ffmpeg/bin/ffmpeg.exe
FFPROBE_PATH=C:/Tools/ffmpeg/bin/ffprobe.exe
```

Оба файла должны существовать. Пути с пробелами допустимы: команды передаются списком аргументов без shell. Проверка установки в PowerShell:

```powershell
& 'C:/Tools/ffmpeg/bin/ffmpeg.exe' -version
& 'C:/Tools/ffmpeg/bin/ffprobe.exe' -version
```

Без этих программ сервер и UI запускаются, но загруженная задача завершается `failed` с кодом `ffmpeg_missing` или `ffprobe_missing` и понятным сообщением. После настройки перезапустите сервер и загрузите запись заново.

Linux / Brev:

```bash
python3.12 -m venv .venv
.venv/bin/python -m pip install -r backend/requirements-dev.txt
cp .env.example .env
cd frontend
pnpm install --frozen-lockfile
pnpm build
cd ..
.venv/bin/python -m backend.app
```

## ML на Linux: установка и офлайн-запуск

`backend/requirements.txt` остаётся лёгким. ML-пакеты вынесены в `backend/requirements-ml.txt`; Windows-окружение разработки и unit-тесты в них не нуждаются. Для сервера выбран Python 3.12, PyTorch/torchaudio 2.8.0 (CUDA 12.8), pyannote.audio 4.0.3 и faster-whisper 1.2.1/CTranslate2 4.6.0. Установлены должны быть NVIDIA-драйвер, совместимый с CUDA 12.8, cuBLAS CUDA 12 и cuDNN 9. Никакого автоматического перехода на CPU нет.

Если зависимости готовятся в разрешённом сетевом окружении, выполните на Linux x86_64:

```bash
python3.12 -m venv .venv
.venv/bin/python -m pip install --upgrade pip
.venv/bin/python -m pip install torch==2.8.0 torchaudio==2.8.0 --index-url https://download.pytorch.org/whl/cu128
.venv/bin/python -m pip install -r backend/requirements-ml.txt
.venv/bin/python -m pip check
```

Эти команды устанавливают библиотеки, а не веса. В этой сессии ML-пакеты и веса не скачивались; совместимость на реальной GPU ещё требует серверной проверки. На сервере без сети используйте заранее подготовленный wheelhouse с полным набором совместимых Linux wheels, включая CUDA-варианты PyTorch и транзитивные NVIDIA-библиотеки:

```bash
.venv/bin/python -m pip install --no-index --find-links=/opt/wheelhouse -r backend/requirements-ml.txt
.venv/bin/python -m pip check
```

Требуемые локальные файлы (Git LFS pointers вместо весов не подходят):

```text
models/whisper-large-v3/
  model.bin
  config.json
  tokenizer.json
  preprocessor_config.json
models/speaker-diarization-community-1/
  config.yaml
  segmentation/pytorch_model.bin
  embedding/pytorch_model.bin
  plda/xvec_transform.npz
  plda/plda.npz
```

Whisper должен быть экспортирован в формат CTranslate2. `config.yaml` pyannote должен описывать `pyannote.audio.pipelines.SpeakerDiarization` с компонентами `segmentation`, `embedding`, `plda`. Поддерживаются ссылки `$model/segmentation` и аналогичные, относительные локальные пути либо словари `checkpoint`/`subfolder` внутри каталога модели. Адаптер разрешает их в проверенные абсолютные локальные пути до вызова pyannote. Ссылки на Hub, URL, токены в конфигурации и неполные компоненты отклоняются. Локальные веса должны быть заранее предоставлены и доступны на чтение; приложение ничего не скачивает и не использует токены.

Настройки в `.env` или переменных процесса:

```dotenv
WHISPER_MODEL_PATH=models/whisper-large-v3
PYANNOTE_MODEL_PATH=models/speaker-diarization-community-1
FFMPEG_PATH=/usr/bin/ffmpeg
FFPROBE_PATH=/usr/bin/ffprobe
HF_HUB_OFFLINE=1
TRANSFORMERS_OFFLINE=1
HF_HUB_DISABLE_IMPLICIT_TOKEN=1
HF_HUB_DISABLE_TELEMETRY=1
PYANNOTE_METRICS_ENABLED=false
OTEL_SDK_DISABLED=true
```

Не добавляйте токены в `.env`. Офлайн-флаги и отключение телеметрии принудительно устанавливаются приложением до ML-импортов. При установке NVIDIA-библиотек через pip задайте путь к ним до запуска (это локальное чтение каталогов, без сети):

```bash
export LD_LIBRARY_PATH="$(.venv/bin/python -c 'import os; import nvidia.cublas.lib, nvidia.cudnn.lib; print(os.path.dirname(nvidia.cublas.lib.__file__) + ":" + os.path.dirname(nvidia.cudnn.lib.__file__))')${LD_LIBRARY_PATH:+:$LD_LIBRARY_PATH}"
.venv/bin/python -m backend.app
```

Рабочий процесс не делает внешних HTTP-запросов. Python audit hook блокирует внешние socket/DNS-вызовы во всех потоках, а внутри Whisper/pyannote — также loopback-соединения. Loopback вне этих адаптеров доступен для ASGI и локального Ollama. Телеметрия отключена; диагностический вывод ML-библиотек подавляется. Дополнительно блокируйте исходящий доступ backend и отдельного процесса Ollama средствами среды развёртывания: Python hook не контролирует нативный код и другой процесс. GPU-память освобождается между этапами, модели запускаются последовательно.

Версии и локальные API сверены с [исходниками pyannote 4.0.3](https://github.com/pyannote/pyannote-audio/tree/4.0.3) и [документацией faster-whisper 1.2.1](https://github.com/SYSTRAN/faster-whisper/tree/v1.2.1). Воспроизводимый серверный прогон и качество русского/казахского распознавания проверяются отдельно на согласованных записях.

Откройте http://127.0.0.1:8000. Сборку нужно выполнить **до запуска backend**; после первой сборки перезапустите сервер. Без сборки корневой URL возвращает `503` с пояснением. OpenAPI доступен на `/openapi.json`; Swagger/ReDoc отключены, чтобы не подгружать скрипты с CDN.

Для разработки frontend: в каталоге `frontend` выполните `pnpm dev`, оставив backend запущенным. Vite слушает `127.0.0.1:5173`, `/api` проксируется на `127.0.0.1:8000`. При изменении порта backend поправьте proxy в `frontend/vite.config.ts`.

Для удалённой машины используйте SSH-туннель с компьютера разработчика (замените USER и HOST):

```bash
ssh -N -L 127.0.0.1:8000:127.0.0.1:8000 USER@HOST
```

Не открывайте публичный порт и не создавайте публичную ссылку.

## Локальный Ollama на Linux

Нужен заранее установленный Ollama с поддержкой `/api/chat`, JSON Schema и `think=false` для qwen3:8b. Модель должна уже присутствовать в локальном хранилище Ollama (полные manifests и blobs). Приложение не вызывает pull/run, не скачивает веса и не использует токены. Отдельный Python SDK не нужен: клиент использует стандартный `http.client`, проверку ответа — уже установленный Pydantic.

Запустите Ollama в отдельном терминале от пользователя, которому доступна заранее подготовленная модель:

```bash
OLLAMA_HOST=127.0.0.1:11434 OLLAMA_NO_CLOUD=1 OLLAMA_DEBUG=false OLLAMA_NUM_PARALLEL=1 OLLAMA_KEEP_ALIVE=0 ollama serve
```

Если веса лежат в другом каталоге, перед этой командой задайте `export OLLAMA_MODELS=/absolute/path/to/ollama-models` с фактическим локальным путём. Если Ollama уже запущен как systemd-служба, задайте эти переменные в её окружении и перезапустите службу; не запускайте второй сервер на том же порту. Переменные `.env` backend не изменяют окружение отдельной службы. Запретите исходящий доступ Ollama на уровне ОС, сохранив loopback, и не включайте отладочное логирование содержимого запросов.

Проверьте наличие модели локально; команда ничего не скачивает:

```bash
OLLAMA_HOST=127.0.0.1:11434 ollama list
```

В списке должна быть `qwen3:8b`. Затем в окружении backend:

```bash
export OLLAMA_BASE_URL=http://127.0.0.1:11434
export OLLAMA_MODEL=qwen3:8b
.venv/bin/python -m backend.app
```

Frontend собирается прежними командами `cd frontend`, `pnpm build`, `cd ..`. Приложение доступно только на `http://127.0.0.1:8000`. Для разработки UI используйте `pnpm dev` из `frontend` при работающем backend.

Адаптер обращается только к числовому адресу `127.0.0.1:11434/api/chat`; прокси окружения игнорируются, перенаправления не выполняются, любые другие URL/модели отвергаются до соединения. Параметры: JSON Schema, `stream=false`, `think=false`, `temperature=0`, `num_ctx=32768`, `num_predict=8192`, `keep_alive=0`. Последний параметр просит освободить модель после ответа. API и режим без облака сверены с [документацией Ollama](https://docs.ollama.com/api/chat), [JSON Schema](https://docs.ollama.com/capabilities/structured-outputs) и [локальным режимом](https://docs.ollama.com/faq#how-do-i-disable-ollama-cloud-features).

Объём JSON с входными репликами ограничен 60 000 байт UTF-8; превышение даёт `analysis_input_too_large`, а не скрытое обрезание записи. Ответ ограничен 2 МиБ; незавершённый ответ, достижение лимита генерации, невалидный JSON и неизвестные ID дают `ollama_invalid_response`. Анализ по частям пока отсутствует, поэтому даже допустимая 15-минутная запись может потребовать более короткого фрагмента для анализа. На пустом транскрипте принимается только пустой результат, без вымышленных тем или поручений.

Проверка Pydantic запрещает неизвестные поля. Источники должны принадлежать текущей встрече, источники поручения — также его теме. Показатели, проблемы и формулировки поручений должны быть дословными фрагментами указанных реплик (либо `не указан`). Исполнители и сроки без текстового основания заменяются на `не указан`. Даты не нормализуются, исходная формулировка сохраняется. Все результаты остаются машинным черновиком с `requires_review=true`: наличие цитаты не гарантирует правильной интерпретации отрицания, контекста или связи имени с поручением.

Саммари хранится в `meetings.summary`, темы и поручения — в существующих `topics` и `action_items`, ключевые пункты с показателями/проблемами — в `key_points`. Таблицы `topic_sources`, `action_sources`, `key_point_sources` сохраняют все ссылки на реплики с внешними ключами; прежнее поле `action_items.utterance_id` и время содержат самый ранний источник. `analyses` отмечает успешно сохранённый анализ. Удаление встречи каскадно удаляет эти данные.

## Конфигурация

`.env.example` содержит только примеры, `.env` исключён из Git. Существующие переменные процесса имеют приоритет. Относительные пути разрешаются от корня репозитория.

| Переменная | Назначение |
| --- | --- |
| `DATA_DIR`, `DATABASE_PATH` | Локальный каталог и SQLite; создаются при запуске |
| `FRONTEND_DIST`, `PORT` | Сборка интерфейса и порт backend; адрес запуска фиксирован на loopback |
| `WHISPER_MODEL_PATH` | Локальный каталог faster-whisper large-v3/CTranslate2 |
| `PYANNOTE_MODEL_PATH` | Полный локальный каталог speaker-diarization-community-1 |
| `OLLAMA_BASE_URL`, `OLLAMA_MODEL` | Только `http://127.0.0.1:11434` и `qwen3:8b`; иные значения отклоняются до HTTP-запроса |
| `OLLAMA_HOST`, `OLLAMA_NO_CLOUD` | Передать отдельному процессу Ollama: `127.0.0.1:11434`, `1`; `.env` backend не настраивает уже работающий Ollama |
| `FFMPEG_PATH`, `FFPROBE_PATH` | Используемые локальные программы; имя в PATH либо абсолютный путь |
| `LIBREOFFICE_PATH` | Будущий локальный экспорт PDF |
| `HF_HUB_OFFLINE`, `TRANSFORMERS_OFFLINE` | Принудительный офлайн-режим загрузчиков |

LibreOffice оставлен для будущего этапа. Ollama вызывается после успешного сохранения транскрипта; backend не запускает Ollama и не загружает его модель.

Все создаваемые пути хранения, включая `DATABASE_PATH`, должны находиться внутри `DATA_DIR`. При изменении `DATA_DIR` поправьте и `DATABASE_PATH` в `.env`; если переменная `DATABASE_PATH` не задана, база создаётся внутри выбранного `DATA_DIR`. Каталог встречи: `DATA_DIR/<UUID>/source.<расширение>`, подготовленное аудио: `DATA_DIR/<UUID>/audio.wav`; будущие результаты также должны храниться там. Временные multipart-файлы находятся в `DATA_DIR/.uploads` и закрываются после запроса. Ссылки и junction внутри хранилища не поддерживаются. Хранилище должно быть доступно на запись только доверенному локальному пользователю приложения.

При старте выполняется миграция таблицы задач без удаления встреч, путей и данных. `processing`/`ready` из исходного каркаса становятся `failed/legacy_state`. Завершённые WAV-задачи сохраняют `ready_for_models` со старым `stage=audio`; для распознавания нужна повторная загрузка. Старые транскрипты с `ready/stage=complete` сохраняются, но возвращают `analysis_completed=false`; для анализа нужна повторная загрузка. Новые задачи получают `ready/stage=analysis_complete` только после анализа. Прерванные активные этапы, включая `analyzing`, становятся `failed/interrupted`; автоматического повтора нет. Сохранённый транскрипт при этом остаётся доступен. Запускайте **один экземпляр приложения, один Uvicorn worker**, без `--reload` во время обработки.

## API

`PLAN.MD` задаёт операции, но не URL. В каркасе выбраны следующие маршруты:

| Метод и путь | Назначение / текущее поведение |
| --- | --- |
| `GET /api/health` | `200`: сервер работает, `processing=local_transcription`, `models=checked_per_job`; это не проверка GPU |
| `POST /api/meetings` | Multipart: `file`, `title`, необязательные `meeting_date` и `timezone`; `202` с `meeting_id`, ID задачи, `status=queued` |
| `GET /api/meetings/{id}/status` | `200`: статус, безопасные `message` и `error_code`; неизвестный ID — `404` |
| `GET /api/meetings/{id}/result` | `200`: прежние поля плюс `summary`, `analysis_completed`, `requires_review`, `key_points`, `topics`, `action_items`; транскрипт доступен с `analyzing`, анализ — после его атомарного сохранения |
| `PATCH /api/meetings/{id}` | Правки говорящих, реплик, поручений и флаг утверждения; `501` |
| `GET /api/meetings/{id}/exports/{format}` | `docx` или `pdf`; `501` |
| `DELETE /api/meetings/{id}` | Удаление встречи; `204`, активная задача/небезопасный путь — `409`, неизвестный ID — `404` |

Ошибки загрузки: пустой файл — `400`, размер — `413`, расширение — `415`, неверные метаданные/multipart — `422`, ошибка записи — `500`. Проверка размера выполняется при чтении multipart без зависимости от Content-Length и повторяется при сохранении. Формат контейнера, аудиодорожка и длительность проверяются в фоне; ошибки видны через status/result с `status=failed`. Диагностика программ, приватные пути и содержимое записей в ответы не включаются. Неизвестные API-маршруты возвращают `404`.

ML-ошибки сохраняются в `job.error_code`: `whisper_model_missing`, `pyannote_model_missing`, `ml_dependencies_missing`, `cuda_unavailable`, `transcription_failed`, `diarization_failed`, `transcript_save_failed`, `network_forbidden`. Анализ добавляет `ollama_configuration`, `ollama_unavailable`, `ollama_model_missing`, `ollama_invalid_response`, `analysis_input_too_large`, `analysis_failed`. Ошибка не содержит traceback, путей или текста записи. `models_connected=true` означает завершённую задачу, а не постоянно загруженные модели; для старых транскриптов отдельно проверяйте `analysis_completed`.

Проверка загрузки: откройте интерфейс, выберите разрешённую обезличенную запись и нажмите «Загрузить запись». При доступных программах, весах и CUDA ожидайте `ready`, затем откройте результат. Эквивалентный запрос из PowerShell (замените путь на существующий файл):

```powershell
curl.exe -X POST http://127.0.0.1:8000/api/meetings -F "title=Проверка подготовки" -F "file=@C:/Recordings/approved.wav"
```

Возьмите `meeting_id` из ответа:

```powershell
curl.exe http://127.0.0.1:8000/api/meetings/MEETING_ID/status
curl.exe http://127.0.0.1:8000/api/meetings/MEETING_ID/result
curl.exe -X DELETE http://127.0.0.1:8000/api/meetings/MEETING_ID
```

## Проверки

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s backend/tests -v
Set-Location frontend
pnpm test
pnpm build
```

На Linux замените путь Python на `.venv/bin/python`. Backend-тесты создают временную SQLite и искусственные байты/тишину без речи. Они проверяют сохранение, ограничения размера/формата/длительности, ошибки FFmpeg/FFprobe, параметры конвертации, статусы, сериализацию задач, миграцию и безопасное удаление. Настоящие FFmpeg, записи, GPU и модели для тестов не нужны: запуск программ подменяется. Это не проверка качества распознавания. React-тесты проверяют отправку файла, сообщения сервера, опрос/остановку/повтор, результат и удаление. Starlette закреплён в зависимостях, поскольку локальный ограниченный multipart-парсер расширяет его API.

Тесты Ollama подменяют HTTP-клиент и анализатор: проверяют JSON, безопасные ошибки, ограничения адреса/размера, отсутствие добавленных поручений, ссылки, транзакции, миграцию и сохранение транскрипта при ошибке анализа. Реальная LLM, сеть и GPU не запускаются. UI-тесты дополнительно проверяют порядок разделов, таблицы, источники, флаги проверки и состояние `analyzing`. Качество реального Qwen3:8b в этой сессии не проверялось.

Временные backend-фикстуры создаются и очищаются внутри игнорируемого `data/.test-tmp`. Если системный диск Windows заполнен и frontend-тесты падают с `ENOSPC`, перед их запуском задайте TEMP/TMP для текущего PowerShell из корня проекта:

```powershell
New-Item -ItemType Directory -Force data/.test-tmp | Out-Null
$env:TEMP = (Resolve-Path data/.test-tmp).Path
$env:TMP = $env:TEMP
```

Это меняет окружение только текущего процесса PowerShell и его дочерних программ.

## Ограничения и закрытый контур

Редактирование и оба экспорта отсутствуют. Подготовка аудио требует FFmpeg/FFprobe; ML требует CUDA, локальных весов и отдельного Ollama. Одна задача обрабатывается за раз; отдельной очереди и отмены нет. Тайм-аут FFprobe — 30 секунд, FFmpeg — 300 секунд; тайм-аут сокета Ollama — 300 секунд, без автоматического повтора. Принудительная отмена ASR/диаризации и серверной генерации Ollama пока не реализована. Список прошлых встреч и восстановление выбранной встречи в UI после обновления страницы отсутствуют; сохранённая встреча доступна по API с её UUID. Файловая система и SQLite не образуют общей транзакции: при ошибке удаления строка сохраняется, удаление можно повторить. При аварийном завершении во время загрузки может потребоваться ручная очистка неполного каталога.

Для будущего полного тракта план требует GPU от 22 ГБ VRAM, RAM от 32 ГБ и 60 ГБ свободного диска (A10G/L4 или лучше). Проверки GPU и моделей в этой сессии не выполнялись. При нехватке VRAM этапы должны последовательно освобождать GPU.

Аудио, транскрипты, саммари и поручения не отправляются во внешние AI/API и не пишутся в логи. Brev — облачная демонстрационная среда, не закрытый контур заказчика; допускаются только обезличенные и согласованные записи. Для закрытого контура заранее подготовьте зависимости, веса и шрифты и проверьте работу при заблокированном исходящем доступе. Аутентификация, live-конференции, рассылки, СЭД, дашборд исполнения и голосовая идентификация не реализованы.
