# Инструкции для агентов

## Контекст проекта

Проект -- прототип системы автопротоколирования совещаний. Он принимает запись из Teams, Zoom или Google Meet и формирует транскрипт с говорящими, саммари по темам, список поручений с ответственными и сроками, а также экспорт в DOCX/PDF.

Перед началом работы прочитать `PLAN.MD` и изучить текущее состояние репозитория. Сохранять существующие пользовательские изменения и не переписывать `PLAN.MD`, если этого явно не попросили.

## Архитектура и технологии

- Интерфейс: React, TypeScript и Vite. Собранный frontend должен отдаваться FastAPI с одного адреса.
- Backend: Python, FastAPI и Pydantic.
- Вход первой версии: загружаемый файл записи. Live-подключение к Teams, Zoom и Google Meet не реализовывать.
- Подготовка аудио: FFmpeg, моно-аудио 16 кГц.
- Распознавание: локальный `faster-whisper` с временными метками.
- Диаризация: локальная `pyannote`.
- Анализ: локальный Ollama с `qwen3:8b`; структурированные ответы валидируются Pydantic.
- Экспорт: DOCX через `python-docx`, PDF через локальное преобразование LibreOffice.
- Хранение: SQLite и локальный каталог файлов. Обрабатывается одна встреча за раз; отдельная очередь задач не требуется.

Разделять источники аудио и обработку: будущий адаптер live-конференций должен передавать аудио с временными метками в тот же модуль обработки.

## Закрытый контур и данные

- Нельзя отправлять аудио, транскрипты, поручения или саммари в OpenAI API, облачный Supabase либо другие внешние AI/API-сервисы.
- Все модели запускаются локально на машине обработки. Веса загружаются заранее, рабочий сценарий должен быть способен работать без сети.
- На NVIDIA Brev разрешены только обезличенные и согласованные для облачной демонстрации записи. Brev не является закрытым контуром заказчика.
- API и интерфейс по умолчанию слушают `127.0.0.1`; для доступа используется SSH-туннель. Не создавать публичную ссылку на приложение.
- Не писать содержимое аудио и транскриптов в логи.
- Не добавлять в Git тестовые записи, веса моделей, результаты обработки, виртуальные окружения и токены.
- Секреты и пути к моделям передавать через переменные окружения; `.env` не коммитить.

## Требования к продукту

- Основной путь: загрузка файла -> задача обработки -> статус -> транскрипт и саммари -> ручная правка -> экспорт DOCX/PDF.
- Интерфейс должен выглядеть как рабочая внутренняя система: загрузка, статус обработки, транскрипт, саммари, таблица поручений и редактирование.
- Не подменять реальную обработку вымышленным протоколом. Если локальная модель не установлена или недоступна, показывать честное состояние или понятную ошибку конфигурации.
- Поддерживать русский, казахский и смешанную русско-казахскую речь. Проверять результат на предоставленных обезличенных записях.
- Диаризация определяет говорящего, но говорящий и ответственный за поручение -- разные сущности.
- Пользователь может сопоставить `speaker_1`, `speaker_2` и другие метки с именами, исправить реплики и поручения до утверждения результата.

## Модель данных

Минимальные сущности: встреча, исходный файл, задача обработки, реплика, говорящий, тема, показатель, проблема, поручение и экспорт.

У поручения обязательны:

- текст;
- ответственный или значение `не указан`;
- срок или значение `не указан`;
- исходная реплика;
- временная метка в записи;
- флаг `требует проверки` при неоднозначности.

LLM не должна придумывать показатели, решения, ответственных или сроки. Относительный срок преобразуется в дату только при известной дате и часовом поясе встречи; исходная формулировка срока сохраняется.

## Формат саммари и экспорта

- Шапка: название, дата, известные участники, отметка о машинной подготовке и проверке секретарем.
- Саммари по ключевым пунктам: короткий вводный абзац и таблица `Направление / доклад | Показатель | Проблема`.
- Для каждой темы: заголовок `Тема N -- название`, краткий абзац с фактами и проблемой, затем таблица `Поручение | Ответственный | Срок`.
- Транскрипт идет приложением с временем и говорящими; поручения должны быть связаны с исходной репликой.
- Заголовки документа синие, заголовки таблиц со светлой заливкой, длинный текст переносится без обрезания. Русские и казахские символы должны отображаться корректно.
